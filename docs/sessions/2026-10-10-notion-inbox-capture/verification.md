**Builds under test:** `feat/21-notion-inbox-capture`.

- **`4337be2`:** VER-001 to VER-045, gate `task check:node` 185/185.
- **`aa38209`:** the capture-name fix, gate `task check:node` 191/191 (tsc, eslint, node:test), re-run by Test. VER-046 and VER-047 were run on this commit, and the scratch harness was re-run on it (6/6).

`aa38209` changes only capture naming, intent recovery and the ledger's latest-record lookups. The live rows checked on `4337be2` weren't repeated, except where VER-046 and VER-047 cover them.

**How it was checked:**

- **Live.** Ran against a throwaway Notion test workspace, never the operator's own, using Notion-Version 2025-09-03. The main checkout's inbox was the one `task notion:setup` had already created (native Status). Test created 31 rows through the API and ran `task notion:pull` 11 times on `4337be2`, then created 5 fresh rows and ran 5 more pulls on `aa38209`. Vault output is gitignored and nothing from it was committed.
- **Fresh clone.** A scratch clone of `4337be2` was used for fresh setup, setup failures, can't-start paths and the release smoke test.
- **Scratch harness.** A Test-owned integration harness, not committed, has the same shape as `integration/notion/test/adapters/pull-e2e.test.ts`: a temp git vault, the real adapters, the in-memory Notion or a local HTTP server, and a fake agent provider. It covers the paths that can't be triggered safely live: a recurring read fault, an outage mid-run, and rate limiting. It also holds the defect probes: A, B, and C (added for the fix).
- **Output hygiene.** All command output was filtered for the key, and no key, Notion ID or hostname is recorded here.

**Result:** all 44 requirements were verified. VER-044 and VER-045 record a defect found on `4337be2`, which failed REQ-011, REQ-016, REQ-017 and REQ-020 outside their fixtures. Two rows with the same title got the same capture filename. That could set a held row to `Ingested`, and it could mark a row `Ingested` when none of its content reached the vault.

Those two rows stay `fail` as the record of that build. VER-046 and VER-047 re-ran the same checks live on `aa38209` with fresh rows, and both pass. `check-traceability.sh` exits 0.
