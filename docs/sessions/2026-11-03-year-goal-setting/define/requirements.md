# Requirements: Year goal setting: primary goal as a Mandala Chart, plus secondary goals

> Part of [index](index.md) · Define

## Requirements

EARS syntax. Each requirement has one acceptance criterion in Given/When/Then form. IDs are never reused; a dropped requirement is struck through, not deleted. A Won't meaning "never" is struck through with its reason; a Won't meaning "later" moves to the Deferred table below.

- **"Year-goals note"** means the one Markdown note that holds a given year's goals: a primary goal, the secondary goals, a status (`draft` or `signed-off`) and a changes section.
- **"Primary goal"** means a Mandala Chart: one **centre goal**, 1 to 8 **pillars** (the sub-goals that serve it), and 0 to 8 **actions** under each pillar. A chart with fewer than 8 pillars, or fewer than 8 actions in a pillar, is "partly filled" and valid.
- **"Secondary goal"** means a one-line goal statement outside the chart, with zero or more areas it touches.
- **"Areas touched"** means `[[wikilinks]]` to `20-areas/` notes, recorded on a pillar or a secondary goal. They mark where relevant knowledge accumulates. They put nothing into the area notes.
- **"Validator"** and **"parser"** mean the framework's check and reader for the year-goals note format. Each is runnable on a single note path. The validator reports **errors**, which reject the note, and **warnings**, which don't.
- **"Goal-setting session"** means the agent-guided conversation in which the operator and the agent draft a year-goals note.
- **"Current goals for a year"** means the year-goals note for that year that is `signed-off` and in `01-vision/`.

| ID | Requirement | Priority | Serves | Acceptance criterion |
|---|---|---|---|---|
| REQ-001 | The framework shall document the year-goals note format, covering every element REQ-002, REQ-004 and REQ-007 name, and shall ship a template note and a complete example note. | Must | OUT-02, NEED-04 | Given the committed format documentation and its example note (8 pillars, at least one with 8 actions, 2 secondary goals, 1 change), when the validator runs on the example and on the empty template, then the example passes with 0 errors and 0 warnings, the template's documented placeholders are listed, and every element in REQ-002, REQ-004 and REQ-007 appears in the documentation. |
| REQ-002 | When the validator checks a year-goals note whose primary goal has one centre goal, between 1 and 8 pillars, and between 0 and 8 actions in each pillar, the validator shall accept the chart. | Must | OUT-01, OUT-02 | Given a 2027 note with centre goal "Run a marathon under 3:30" and 3 pillars ("Endurance" with 5 actions, "Strength" with 8, "Recovery" with 0), when the validator runs on it, then it exits 0 and reports 0 errors. |
| REQ-003 | If a year-goals note has no centre goal, more than one primary goal, more than 8 pillars, more than 8 actions in a pillar, an empty pillar or action, a missing or invalid year, or a status other than `draft` or `signed-off`, then the validator shall reject the note, name each violation with where it is in the note, and exit non-zero. | Must | OUT-02 | Given a 2027 note with 9 pillars and a pillar "Strength" with 9 actions, when the validator runs on it, then it exits non-zero and reports two errors: one naming "primary goal: 9 pillars, maximum 8" and one naming pillar "Strength": 9 actions, maximum 8. |
| REQ-004 | The validator shall accept zero or more secondary goals in a year-goals note, each a one-line statement with zero or more areas touched. | Must | NEED-01, OUT-02 | Given a 2027 note with a valid primary goal and secondary goals "Read 24 books" (areas touched: `[[reading]]`) and "Learn conversational Spanish" (no areas), when the validator runs on it, then it exits 0, and the parser returns 2 secondary goals with 1 and 0 areas touched. |
| REQ-005 | Where a pillar or secondary goal names an area touched that has no note in `20-areas/`, the validator shall report a warning naming the pillar or goal and the area, and shall not reject the note. | Should | OUT-02 | Given `20-areas/` has `health.md` but no `sailing.md`, and pillar "Recovery" names `[[health]]` and `[[sailing]]`, when the validator runs, then it exits 0 and reports exactly one warning, naming pillar "Recovery" and area "sailing". |
| REQ-006 | When the parser reads a valid year-goals note, it shall return the year, the status, the sign-off date if any, the centre goal, each pillar in note order with its actions and areas touched, each secondary goal with its areas touched, and the changes. | Must | OUT-02, NEED-03 | Given the documented example note for 2027, when the parser reads it, then it returns year 2027, status `signed-off`, sign-off date 2026-12-20, the centre goal text, 8 pillars in the note's order with their action counts and area lists matching the note, 2 secondary goals and 1 change. |
| REQ-007 | The validator shall accept a changes section in a year-goals note made of entries that each have a date and a description, and shall reject an entry whose date is not a valid `YYYY-MM-DD` date. The parser shall return the entries oldest first. | Must | NEED-03, OUT-02 | Given a signed-off 2027 note with changes "2027-05-02: dropped pillar Strength, injury" and "2027-03-10: added action 'park run weekly' to Endurance", written in that order, when the parser reads it, then it returns the 2027-03-10 entry first. And given a third entry dated "2027-13-01", the validator rejects the note and names that entry. |
| REQ-008 | If `01-vision/` holds more than one signed-off year-goals note for the same year, then the validator shall report an error naming each of them. | Should | OUT-02, NEED-03 | Given two signed-off notes for 2027 in `01-vision/`, when the validator checks the folder, then it exits non-zero with one error that names both files and the year 2027. |
| REQ-009 | When the operator starts the goal-setting session for a year, the agent shall guide them in conversation through the centre goal, the pillars, the actions for each pillar, the areas each pillar touches, and the secondary goals. | Must | NEED-01, OUT-01 | Given `20-areas/` holds `health.md` and `career.md`, when the operator starts the session for 2027 and answers each prompt, then the agent asks, in order, for the centre goal, the pillars, each pillar's actions, each pillar's areas touched (offering `health` and `career` as existing areas), and the secondary goals. The operator can stop a pillar at fewer than 8 actions. |
| REQ-010 | When the goal-setting session ends, the agent shall write the drafted year-goals note to the root of `00-inbox/` with status `draft`, as a note that the validator accepts. | Must | OUT-01, NEED-02 | Given a session for 2027 that ends with a centre goal, 3 pillars and 1 secondary goal, when it finishes, then exactly one new note for 2027 is in the root of `00-inbox/` (not in `00-inbox/capture/`), its status is `draft`, and the validator exits 0 on it. |
| REQ-011 | If the goal-setting session stops before every step is answered, then the agent shall still write what was agreed so far to `00-inbox/` as a `draft` note that the validator accepts, provided at least a centre goal and one pillar were agreed. | Should | OUT-01 | Given a 2027 session in which the operator has given a centre goal and 2 pillars with no actions, when they end the conversation early, then a `draft` 2027 note with that centre goal and those 2 pillars is in the root of `00-inbox/`, and the validator exits 0 on it. |
| REQ-012 | While a year has no signed-off year-goals note in `01-vision/`, the parser's current-goals lookup for that year shall return no goals, whatever drafts exist elsewhere. | Must | NEED-02, OUT-02 | Given a `draft` 2027 note in `00-inbox/` and nothing in `01-vision/`, when the current-goals lookup runs for 2027, then it returns no goals and says no signed-off note exists for 2027. |
| REQ-013 | When the operator signs off a draft year-goals note, the framework shall set its status to `signed-off`, record the sign-off date, and place it in `01-vision/` as that year's current goals, leaving no copy in `00-inbox/`. | Must | OUT-01, NEED-02 | Given a valid `draft` 2027 note in `00-inbox/` and an empty `01-vision/`, when the operator signs it off on 2026-12-20, then `00-inbox/` no longer holds it, `01-vision/` holds it with status `signed-off` and sign-off date 2026-12-20, and the current-goals lookup for 2027 returns its centre goal. |
| REQ-014 | If the operator signs off a draft for a year that already has a signed-off year-goals note in `01-vision/`, then the framework shall refuse, leave both notes unchanged, and tell the operator to record the change in the existing note's changes section. | Should | NEED-02 | Given a signed-off 2027 note in `01-vision/` and a new `draft` 2027 note in `00-inbox/`, when the operator signs off the draft, then both files are byte-for-byte unchanged and the operator is told that 2027 already has signed-off goals and changes go in its changes section. |
| REQ-015 | The goal-setting session and sign-off shall not create, edit, move or delete any file in `20-areas/`. | Must | OUT-03, NEED-01 | Given `20-areas/` with `health.md` and `career.md`, when a 2027 session names both as areas touched and the draft is then signed off, then a checksum of every file in `20-areas/` is the same before and after, and no new file exists there. |
| REQ-016 | The framework shall ship `01-vision/` holding only a README that says what belongs there, and shall keep every other file in `01-vision/` out of git. Measure: see [quality.md](quality.md#nfr-measures). | Must | OUT-03, NEED-04 | Given a fresh clone, when `01-vision/2027-goals.md` and a draft in `00-inbox/` are created, then `git status --porcelain` lists neither, `git ls-files 01-vision/` lists only `01-vision/README.md`, and `00-inbox/`, `10-projects/`, `20-areas/`, `30-resources/` and `40-archive/` keep their names. |
| REQ-017 | The year-goals note shall be plain Markdown with the vault's frontmatter, in which the centre goal, every pillar, every action, every area touched and every secondary goal can be read as text in a standard Markdown preview, without mycelia or Obsidian plugins. Measure: see [quality.md](quality.md#nfr-measures). | Must | NEED-01, NEED-04 | Given the documented example note, when it's opened in GitHub's Markdown preview and in Obsidian with no community plugins, then the centre goal, all 8 pillars, every action, every area link and both secondary goals are visible as text, and its frontmatter has `name`, `description`, `type`, `created` and `updated`. |
| REQ-018 | The framework's `task check:node` gate shall run parser and validator tests that cover a full 8 × 8 chart, a partly filled chart, secondary goals, the changes section, and each rejection case in REQ-003 and REQ-007. Measure: see [quality.md](quality.md#nfr-measures). | Must | OUT-02 | Given the committed tests, when `task check:node` runs, then it passes, and the test names include one case for each of: full chart, partly filled chart, secondary goals, changes order, and each REQ-003 and REQ-007 violation. Breaking the 8-pillar limit in the validator makes at least one test fail. |
